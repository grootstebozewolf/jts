# Curve arc-length reference vectors (M-LEN-CS / M-LEN-CC).
#
# Provenance: values are the float arc length s = r * theta as emitted by the
# NetTopologySuite.Proofs oracle (RocqRefRunner), ARC_LENGTH mode, from the
# Qed-closed arc primitives in theories/ArcLength.v (arc_length := r*theta,
# chord_le_arc_length, chord_subtended_sq) + theories/Atan2.v + AngleBetween.v.
#   repo:  https://github.com/grootstebozewolf/NetTopologySuite.Proofs  (issue #64, PR #75)
#   build: gh run download <run> -n oracle-bin-linux ; then per case:
#            printf 'ARC_LENGTH\n%s\n%s\n%s\n' "sx sy" "mx my" "ex ey" | ./oracle_bin
#
# IMPORTANT -- ARC_LENGTH is the oracle's *interface-boundary* float mode: arc
# length is transcendental and has NO Coq-extractable exact form, so the value
# goes through a sanctioned hand-rolled sqrt/acos (see the Proofs repo's
# oracle-handrolled-allowlist.txt). That acos loses accuracy for near-flat,
# huge-radius arcs -- enough to dip *below* the chord, which violates the proven
# chord_le_arc_length. The "large_r_nearflat" case below is therefore anchored
# to the analytically/atan2-correct value (which the JTS impl computes), not to
# the float-oracle output. The certifiable per-arc quantities (r^2, cos theta,
# major-arc flag as exact rationals) come from ARC_LENGTH_INVARIANTS_EXACT.
#
# These vectors are the differential reference for CircularString.getLength().
# To refresh, re-run the oracle as above; the JTS impl uses Orientation.index
# (scale-invariant) for arc/chord degeneracy, per ArcOrient.arc_side_chord_mid_nonzero.
#
# Format: sx sy  mx my  ex ey  expected_length  # comment
# Note: which arc (minor vs major) is fixed by the mid control point.
